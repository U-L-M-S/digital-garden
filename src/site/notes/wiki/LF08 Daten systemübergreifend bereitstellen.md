# IV. [[wiki/Softwareergonomie\|Softwareergonomie]] von Benutzerschnittstellen
>In diesem Kapitel lernen wir den Begriff [[wiki/Softwareergonomie\|Softwareergonomie]] kennen.
>>Wie der Name schon sagt, geht es darum, Software so einfach zu gestalten, dass der Nutzer sofort verstehen kann was er tun kann und was zu tun ist. 
>>Natürlich spielt [[wiki/UX\|UX]] eine Rolle in dieser Thematik sowie andere Themen wie [[wiki/Corporate Design\|Corporate Design]].
___

Als nächste soll man verstehen was den Begriff [[wiki/GUI\|GUI]] bedeutet und wie diese aufgebaut ist. Diese kann man in 4 Schritten aufteilen.
- Sketch: 
	- Erste Entwurf im Designprozess.
	- Verständnis, was der Benutzer sieht.
	- Auf Papier.
- Wireframe: 
	- Einfach Design von der Sketch.
	- Keine Farbe.
	- Kein Inhalt ([[wiki/Lipsum\|Lipsum]])
	- Einfacher Struktur
	Wireframe kann [[wiki/statisch\|statisch]]e (Darstellung von nur einer einzelnen Oberfläche.) **oder** [[wiki/dynamic\|dynamic]] (Mehrere Oberfläche werden miteinander verknüpft) sein- 
- Mockup: Eine Wireframe wird erstellt und wird als bsp, mit den Kundenorientierung, erstellt (GUI wird erstellt).
- Prototyp: 
	-  Funktionen und Verlinkung werden eingesetzt.
